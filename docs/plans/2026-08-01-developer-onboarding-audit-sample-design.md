# Developer Onboarding Audit Sample Design

## Goal

Publish a truthful, compact capability sample that shows how LaunchClear can evaluate a developer tool's first-run experience and turn observed friction into prioritized product actions.

## Chosen approach

Use a fully fictional CLI product and a synthetic evidence timeline. The sample demonstrates the method without implying access to a real company's product, customer data, or private systems. A bilingual public intake form converts the sample into a fixed-scope service entry point.

## Alternatives considered

1. Review a real public developer tool. This would create stronger product specificity, but it would require a fresh recorded session, permission checks, and careful separation between public feedback and a paid service.
2. Publish only a generic checklist. This is faster, but it provides weak evidence that the method can produce prioritized findings.
3. Publish a fictional evidence-backed report and reusable intake form. This gives a concrete deliverable, preserves truthful boundaries, and keeps production cost low. This is the selected option.

## Deliverables

1. A fictional first-run evaluation report with a dated evidence timeline, task definition, scoring, prioritized findings, recommendations, and acceptance checks.
2. A fixed-scope offer for one developer onboarding audit at USD 99 or RMB 699.
3. English and Chinese GitHub issue forms that collect only public or sanitized information.
4. README links that make the sample and request paths easy to find.

## Truth and safety boundaries

The fictional product is clearly labelled. No customer relationship, commissioned work, product access, conversion result, or payment is claimed. Public requests must not include credentials, private repositories, customer data, personal data, private URLs, confidential logs, or production exports. Work starts only after written scope, payment, access, and acceptance confirmation.

Validate both issue forms as YAML, check all repository-relative links, scan the new material for placeholder language, and review the final diff before publication.
